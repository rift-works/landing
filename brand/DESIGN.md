## 2. Strategic visual objective

Make RiftWorks feel like a capable engineering partner that understands difficult business problems and can build the solution. The identity must communicate:

1. Structural intelligence.
2. Technical execution.
3. Business seriousness.
4. Scalable systems.
5. International ambition with a clear Central American origin.

Do not make the brand look like a low-cost software factory, a generic AI startup, a creative agency, a crypto company, a geology company, or a gaming brand.

## 3. Non-negotiable visual constraints

- Use an abstract system of convergence, structure, and platform.
- Do not depict literal cracks, broken objects, volcanoes, maps, palms, brains, circuits, robots, lightning, flames, globes, handshakes, infinity symbols, or generic arrows.
- Avoid literal `RW` monograms unless a future design proves exceptional at small sizes and legally distinct.
- Use a wordmark plus an independent isotipo.
- The wordmark must work without the isotipo.
- The isotipo must remain recognizable at favicon and app-icon scale.
- Prefer geometric construction, stable negative space, and controlled asymmetry.
- Use light-first composition with dark compatibility.
- Never use color as the only carrier of meaning in data or interface artifacts.

## 4. Color tokens

### Base palette

| Token | HEX | Role |
| --- | --- | --- |
| `--rw-deep-navy` | `#0B1F33` | Primary dark surface, headings, high-impact sections |
| `--rw-signal-blue` | `#1F6FEB` | Primary action and technology accent |
| `--rw-coast-teal` | `#16B8A6` | Data accent, positive/active state, secondary signal |
| `--rw-steel-slate` | `#718096` | Secondary text, rules, metadata |
| `--rw-cloud-white` | `#F7FAFC` | Primary light surface and document background |

### Accessibility rule

Use Deep Navy for body text on Cloud White. Do not use Coast Teal or Steel Slate as normal-sized text on Cloud White without testing and adjusting the token. Signal Blue is for large text, UI controls, links, or tested contexts; verify WCAG 2.2 AA before release.

## 5. Typography

- Headings and brand display: **Manrope**, SemiBold/Bold.
- Body, UI, and long-form copy: **Inter**, Regular/Medium.
- Technical labels, metrics, and code: **IBM Plex Mono**.
- Use real font files or approved webfont sources; document licenses before production.
- Do not mix more than these three families in one artifact.
- Display headings should be compact and architectural, never playful or inflated.

## 6. Layout, shape, and surface language

- Use an 8px base spacing unit.
- Suggested spacing scale: 4, 8, 12, 16, 24, 32, 48, 64, 96, 128px.
- Use a 12-column desktop grid and a 4-column mobile grid.
- Prefer rectangular surfaces with restrained 4–12px corner radii.
- Avoid excessive pills, floating blobs, glassmorphism, and decorative gradients.
- Borders should be quiet and structural; use thin slate or navy-tinted lines.
- Shadows should be minimal, cool, and functional.
- Create visual hierarchy through scale, alignment, negative space, and contrast—not ornament.

## 7. Three logo proposals

These are concept directions, not approved final logos. Their preliminary scores are design hypotheses based on the stated criteria and must be recalculated after actual sketches, similarity checks, and small-size tests.

### Evaluation model

| Criterion | Weight |
| --- | ---: |
| Strategic fit | 25% |
| Scalability across sizes and media | 20% |
| Distinctiveness | 20% |
| Legibility | 15% |
| Accessibility and contrast resilience | 10% |
| Trademark distinctiveness potential | 10% |

Scores use a 1–5 scale. They are not legal opinions or final design judgments.

### Proposal A — Tectonic Platform

**Concept:** Two solid geometric planes approach each other and lock into a stable horizontal platform. The negative space between them suggests a controlled rift without depicting a crack.

**Meaning:** Convergence, architecture, balance of forces, and the transformation of complexity into a reliable foundation.

**Construction rules:**

- Two primary blocks, one left and one right.
- One controlled diagonal or stepped interface between blocks.
- A clear lower platform or shared baseline.
- No thin strokes; use filled geometry.
- Maintain recognizable silhouette at 16px.
- Favor a 1:1 or 4:3 bounding box for the isotipo.

**Preliminary score:**

| Criterion | Score |
| --- | ---: |
| Strategic fit | 5 |
| Scalability | 5 |
| Distinctiveness | 4 |
| Legibility | 5 |
| Accessibility resilience | 5 |
| Trademark distinctiveness potential | 4 |
| **Weighted estimate** | **4.65 / 5** |

**Open Design prompt:**

> Create a premium B2B technology brand logo for RiftWorks. Explore an abstract isotipo made from two filled geometric planes that converge and form a stable platform. The mark should communicate structural intelligence, engineering rigor, balance, and execution. Use controlled negative space to suggest a rift without showing a crack. Pair it with a clean Manrope wordmark reading “RiftWorks”. Use Deep Navy #0B1F33, Signal Blue #1F6FEB, and Cloud White #F7FAFC. Produce black, white, monochrome, favicon, horizontal lockup, and isolated-symbol variants. Avoid literal cracks, geology, maps, circuits, brains, robots, flames, lightning, gradients, gamer aesthetics, crypto aesthetics, and generic AI symbols. The result must be geometric, flat, scalable, legible at 16px, and suitable for trademark review.

### Proposal B — Structural Grid

**Concept:** A compact modular grid where two offset structural units interlock to create a central passage. It expresses systems, integration, data flow, and repeatable architecture.

**Meaning:** RiftWorks does not merely build one object; it creates a system of connected capabilities.

**Construction rules:**

- Use 3–5 modular units maximum.
- Use consistent module proportions and a visible alignment logic.
- Allow a central negative-space channel.
- Do not form an obvious `RW` monogram.
- The mark should work as an app icon, dashboard avatar, and social avatar.

### Proposal C — Convergence Gate

**Concept:** Two vertical structural masses create a precise central aperture. The aperture becomes a gateway from fragmented current state to engineered future capability.

**Meaning:** Discovery, entry into a stronger system, transformation, and a clear route through complexity.

**Construction rules:**

- Use two primary vertical masses and one central aperture.
- Keep the aperture wide enough to survive small-size reproduction.
- Avoid a literal doorway or arch.
- Use strict optical centering and a strong vertical axis.
- Test the symbol in app-icon, favicon, document stamp, and presentation-cover contexts.

## 8. Recommended selection process

1. Generate 6–10 sketches per direction, not one logo per direction.
2. Reject any concept that depends on color or fine detail.
3. Test each finalist at 16px, 24px, 48px, 128px, and presentation-cover scale.
4. Test black, white, Deep Navy, Signal Blue, and single-color versions.
5. Run a similarity and trademark search before selecting a final mark.
6. Ask Gabriel and Axel to score each finalist independently using the six weighted criteria.
7. Select one direction, then redraw it as clean vector geometry; do not treat an AI raster output as the final logo.

## 9. Open Design package instructions

Open Design uses portable `DESIGN.md` systems. The official project documents that brand systems are saved under `design-systems/<brand>/` and that new packages are best shipped with `DESIGN.md`, `manifest.json`, and `tokens.css`. A legacy `DESIGN.md`-only system remains compatible, but this file is intentionally written so it can become the canonical design prose. [Open Design FAQ](https://open-design.ai/faq/), [Open Design design-systems guide](https://github.com/nexu-io/open-design/tree/main/design-systems)

### Suggested Open Design flow

1. Open the Open Design desktop app and connect the coding agent you use.
2. Create or select a design-system project for RiftWorks.
3. Load this `DESIGN.md` as the brand contract.
4. Generate each proposal separately using its prompt.
5. Keep all outputs as separate proposal artifacts; do not overwrite the source contract.
6. Review the generated sketches against the numeric matrix and constraints above.
7. After founder selection, update this file with the chosen direction and create the final token and asset files.

### Practical runbook for Windows

1. Install the Open Design desktop app from [open-design.ai](https://open-design.ai/).
2. Connect the local coding agent you will use, such as Codex, through the Open Design setup screen.
3. Create a local Open Design project for RiftWorks.
4. Add this file as the project's brand contract under `design-systems/riftworks/DESIGN.md`.
5. Start with the **Prototype** or **Design System** workflow, not a generic free-form image prompt.
6. Generate Proposal A, B, and C separately. Keep each result in a separate folder or artifact name.
7. Use the adjustment loop to make one change at a time: geometry, spacing, typography, color, or lockup—not all at once.
8. Export the selected direction as editable vector-oriented output and preserve the prompt, source files, and preview.
9. Recreate the chosen mark manually as clean SVG geometry before treating it as the final logo.
10. Add the approved token and asset files to this repository only after founder review.

### Prompt template for each Open Design iteration

```text
Use the RiftWorks DESIGN.md brand contract as the sole visual source of truth.
Work only on [Proposal A / Proposal B / Proposal C].
Create [one isolated logo concept / a comparison sheet of 6 variations / a lockup sheet].
Preserve the required geometry, color tokens, typography, exclusions, and accessibility constraints.
Show the output in black, white, Deep Navy, and one accent treatment.
Include a 16px favicon test, a 48px app-icon test, a horizontal lockup, and clear-space guidance.
Do not introduce new symbols, gradients, clichés, or unapproved copy.
Explain which constraints were satisfied and which require human review.
```
